# Вопросы, над которыми необходимо подумать в ходе решения задания:
1. Что делать, если файл очень большой?
2. Какие тесты мы можем написать?
3. Можем ли мы выводить имена в порядке убывания частоты?

# Решение: 

Разбил файл на под файлы и многопточно обработал, используя Worker Pool для быстрого выполнения кода с большими данными.

Использовал мапу для того, чтобы хранить значение, где ключ --- имена, значение --- счетчик.

---

Где что находится
 - `go.mod` — корневой модуль проекта.
 - `cmd/app/main.go` — точка входа CLI; парсит флаги и вызывает логику.
 - `internal/namescounter/` — основная бизнес-логика: чтение файла, разбиение на чанки и подсчёт.
 - `internal/output/` — форматирование и вывод результатов (сортировка/без сортировки).
 - `resources/files/file_with_names.txt` — пример входного файла с именами.

Для чего нужно
 - Быстрый инструмент для подсчёта повторов в больших текстовых файлах.
 - Демонстрация потоковой обработки, Goroutine/каналов и разделения ответственности по пакетам.

Как запустить

Запуск из корня проекта:

```bash
go run ./cmd/app -file resources/files/file_with_names.txt
```

Опции:
- `-file` — путь к входному файлу (обязательно).
- `-sort` — при установке сортирует вывод по частоте (по убыванию).
- `-workers` — количество воркеров (по умолчанию равно числу CPU).

Тестирование

В проекте есть unit-тесты для CLI, подсчёта строк и форматирования вывода.
Они покрывают основные сценарии: успешный запуск, отсутствие файла, подсчёт повторов, сортированный и несортированный вывод.

Запуск всех тестов:

```bash
go test ./...
```

При изменениях в логике рекомендуется сначала запускать именно эту команду, чтобы проверить весь проект целиком.
